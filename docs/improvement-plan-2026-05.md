# Round 2 — 적대적 레드팀 (냉소적 베테랑 / 적대 심사관 / 이탈 사용자 / 경쟁사 PM)

Round 1은 건설적, Round 2는 공격. **세 직군이 독립적으로 같은 급소를 찔렀다.**

## 🔴 P0 — 지금 당장 (Wave보다 우선, 출시 전 필수)

1. **[측정 신뢰 붕괴] DSP clock-drift 보정 死코드** — 보정 인프라를 만들고 `analyzeSimplified`에서 미적용 → **현재 모든 rate에 systematic bias**. 베테랑·경쟁사 PM·측정전문가 3인 공통 지목. "더 잘 만들 수 있는데 안 한"이 아니라 "지금 틀린 값을 파는" 상태. 곱셈 해자(측정×생활×커뮤니티)는 측정이 틀리면 전부 붕괴. → **최우선 적용 + fixture 테스트(Rule #1).** (단, DSP는 사용자 검증 동반 권장)

2. **[이탈 결정타] 첫 측정이 "실패"로 끝남** — `MeasurementViewModel.persist()` 게이트(±2 s/d 정밀도 AND beatYield 50% AND …)가 평범한 환경의 첫 측정을 통째 폐기 → "재측정" 버튼만 남음. 입문자는 "앱이 못 만든 것"으로 읽고 삭제. tickIQ는 대충 잡아도 값을 준다. → **첫 N회는 게이트 우회 → reliabilityGrade(A/B/C/F) 배지 + "±N s/d"로 무조건 값 표시.** "신뢰 낮음"이 "실패"보다 100배 낫다.

3. **[커뮤니티 확정 리젝 3 — 출시 전]**
   - **뷰어 EULA·신고 동의 누락**: 탭 진입 즉시 익명가입+피드 노출, EULA는 게시 직전만 → 1.2 위반. EULA/신고 동의를 **소비(view) 진입 시점**으로.
   - **PrivacyInfo.xcprivacy 거짓신고**: 커뮤니티 사진이 author_uid에 영구 연결되는데 `Linked=false` → 메타데이터 리젝. **Linked=true**로.
   - **권한 목적 문자열**: 카메라/사진 설명이 "기기에만 저장"인데 외부 업로드 → 5.1.1. 목적 갱신.
