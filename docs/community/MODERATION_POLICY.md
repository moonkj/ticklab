# TickLab 콘텐츠 모더레이션 정책 (Content Moderation)

> 커뮤니티(B 영역) 콘텐츠 제한·관리 정책. 운영 관리자(신고 큐·제재·감사) 사양의 콘텐츠 정책 레이어.
> 측정 데이터(A 영역, 온디바이스)는 모더레이션 대상이 아니며 운영자도 접근 불가.

## 핵심 방침
- **거래 전면 금지** — 시계 매매·교환·시세 흥정·연락처 유도·거래 알선 일체 금지. 사기·금전 분쟁 원천 차단.
  의견·리뷰·정보 공유·측정 결과 공유는 자유.
- **3단계 방어** — ① 자동 필터(업로드 시점) ② 사람 검수(신고 큐) ③ 사용자 신고.
- **단계적 제재** — 경고 → 콘텐츠 처리(soft-delete) → 일시정지 → 영구 차단. 각 단계 사유 통지 + 이의신청.
- **데이터 경계** — 모더레이션은 커뮤니티(B)에만. 측정값·raw 오디오는 대상 아님(서버에 없음).

## 구현 현황 (코드)
| 항목 | 위치 | 상태 |
|---|---|---|
| 이미지 검열(선정성) | `CommunityModerationService` (SensitiveContentAnalysis, 온디바이스) | ✅ |
| 욕설/금칙어 필터(정규화+반복축약) | `CommunityTextModerator.containsProfanity` | ✅ |
| **거래 금지 자동 탐지**(거래 키워드·연락처 유도·전화번호) | `CommunityTextModerator.containsTradeIntent` → 작성 시 차단 | ✅ |
| 작성화면 **가이드라인 고지** | `CommunityComposerView.communityGuidelineNote` | ✅ |
| 신고 사유 **거래/사기** 추가 | `Community.ReportReason.trade/.scam` (전 로케일) | ✅ |
| 신고 큐 + 글 단위 집계 + 숨김/삭제 | 운영 대시보드(`AdminOpsView`) + Supabase RLS | ✅(SQL 배포 필요) |
| 신고 누적 자동 숨김(3건) | `schema.sql` 트리거 | ✅ |

### 거래 탐지 규칙 (보수적 — 흑백 분명한 것만 차단)
- **차단**: 거래 키워드(팝니다/삽니다/직거래/택배비/양도/매매/분양 등), 연락처 유도(카톡/디엠/연락처/전화주 등), 전화번호 패턴.
- **통과(→ 신고/검수로)**: 단순 가격 언급("신품가 1500만원")·감상("비싸서 못 사요"). 오탐으로 정상 글 막지 않기 위함.
- 위치: 커뮤니티 작성 시점(`CommunityTextModerator.screen` → `.tradeBan`).

## 백엔드/외부/문서 (앱 외)
- **제재 단계(일시정지·영구차단) + 감사 로그** → Supabase 테이블 + **웹 어드민 콘솔**(앱 미구현, 운영 사양서 5·6).
- **CSAM 해시 매칭(PhotoDNA 등)** → 외부 신뢰 서비스 필수(자체 판별 불가). Edge Function 연동 검토.
- **ML 독성 분류(맥락 기반 혐오·괴롭힘)** → P2, 서버 측. 자동 차단이 아니라 검수 큐 우선순위용.
- **법무 선결(P0)** → 커뮤니티 가이드라인 문서·약관(거래 면책·연령 17+)·이의신청 절차. 코드보다 먼저.

## 우선순위
- `P0`(출시 전): 거래 금지 탐지·고지 ✅ / 신고 처리 ✅ / 가이드라인·약관 문서(법무) / CSAM 경로(외부).
- `P1`: 욕설 필터 고도화 ✅(반복축약) / 스팸 rate-limit(백엔드) / 제재 체계(백엔드·웹).
- `P2`: ML 분류 / 검수 큐 우선순위 자동화.
